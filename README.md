# Project: No AMR

โมดูลสำหรับพยากรณ์โปรไฟล์การใช้ไฟฟ้า (P / OP / H) ของผู้ใช้ไฟที่ **ไม่มีข้อมูล AMR**
(Automatic Meter Reading) ของตัวเอง โดยอาศัยข้อมูล AMR ของผู้ใช้ไฟที่มีลักษณะธุรกิจ
และอัตราค่าไฟใกล้เคียงกันเป็นต้นแบบ (proxy) แล้วปรับสเกลตามขนาดสัญญา (KVA)

ที่มาของแนวคิด: เมื่อไม่ทราบข้อมูล AMR ของผู้ใช้ไฟรายหนึ่งโดยตรง ให้จำแนกผู้ใช้ไฟ
ตาม **ประเภทธุรกิจ** (เช่น โรงแรม, โรงพยาบาล, โรงงาน) และ **ประเภทอัตราค่าไฟ**
(rate code) ก่อน แล้วจึงนำโปรไฟล์การใช้ไฟฟ้าเฉลี่ยของกลุ่มธุรกิจนั้น (กำลังไฟฟ้าสูงสุด
และพลังงานไฟฟ้า แยกตามช่วง Peak / Off-Peak / Holiday) มาใช้เป็นค่าพยากรณ์

## หลักการจับคู่ (matching priority)

1. **EXACT** — ตรงทั้งประเภทธุรกิจและประเภทอัตรา
2. **BUSINESS_ONLY** — ตรงประเภทธุรกิจ แต่ไม่ทราบ/ไม่ตรงอัตรา
3. **RATE_ONLY** — ไม่ทราบ/ไม่ตรงประเภทธุรกิจ แต่ตรงอัตรา
4. **DEFAULT** — ไม่พบข้อมูลที่ตรงกันเลย ใช้ค่ากลาง (แถว `DEFAULT`/`DEFAULT` ใน load_profiles.csv)

ผลลัพธ์จะบอก `match_level` เสมอ เพื่อให้รู้ว่าเป็นค่าพยากรณ์ที่แม่นยำระดับใด
และถ้าไม่ใช่ exact match จะมี warning แจ้งไว้ด้วย

## การปรับสเกลตามขนาดสัญญา (KVA)

ถ้าทราบทั้ง `contract_kva` ของลูกค้า และ `contract_kva_ref` ของโปรไฟล์ที่จับคู่ได้
ผลลัพธ์ demand/energy จะถูกคูณด้วย `customer_kva / reference_kva` เพื่อสะท้อนขนาด
ธุรกิจจริง ไม่ใช่ยกค่าดิบจากโปรไฟล์อ้างอิงมาใช้ตรงๆ

## การนำเข้าข้อมูล AMR จริง (pea_ingest)

`src/amr_mapping/pea_ingest.py` อ่านไฟล์ export จากระบบ PEA 2 รูปแบบ (ไฟล์นามสกุล
`.xls` แต่เนื้อหาจริงเป็น HTML table):

- **"แบบฟอร์มการอ่านหน่วยมิเตอร์ AMR"** — ตารางประวัติค่าสะสมรายเดือน (Rate A/B/C)
  ใช้คำนวณพลังงาน (ผลต่างระหว่างเดือน) และกำลังไฟฟ้าสูงสุด (อ่านค่าตรงๆ) ต่อเดือน
  โดย RATE A = ช่วง Peak (P), RATE B = Off-Peak (OP), RATE C = Holiday (H)
  (ยืนยันจากรูปแบบข้อมูลจริง: Rate A ใช้เฉพาะวันทำการ 09:00-22:00, Rate B ใช้ช่วง
  นอกเวลานั้นในวันทำการ, Rate C ใช้ทั้งวันในวันหยุด/เสาร์-อาทิตย์)
- **"รายงานข้อมูลกิโลวัตต์ชั่วโมงแบบช่วงเวลา"** — ข้อมูลละเอียดราย 15 นาที ใช้ตรวจสอบ
  ความถูกต้องข้าม-format ได้ (ผลรวม/ค่าสูงสุดต้องตรงกับที่คำนวณจากไฟล์ประวัติรายเดือน)

ค่าที่อ่านได้จากมิเตอร์เป็น "ค่าดิบ" ต้องคูณด้วย**ตัวคูณมิเตอร์** (CT ratio × VT ratio
เช่น `50:5 A.` × `22000:110 V.` = 2000) จึงจะได้ค่ากำลังไฟฟ้า/พลังงานไฟฟ้าจริง —
`compute_meter_multiplier()` คำนวณให้อัตโนมัติจากสตริงอัตราส่วน

### วิธีอัปเดต load_profiles.csv ด้วยข้อมูลจริง

`load_profiles.csv` เท่านั้น — **ไม่เขียนชื่อ/เลขบัญชี/เลขมิเตอร์ของลูกค้าลงไฟล์ผลลัพธ์**
จึง commit ไฟล์ผลลัพธ์เข้า repository (แม้เป็น public) ได้อย่างปลอดภัย ส่วนไฟล์ดิบที่มี
ข้อมูลระบุตัวตนลูกค้า **ไม่ควร commit เข้า repo นี้เด็ดขาด** ให้เก็บไว้นอก repo เท่านั้น

## เว็บแอป

หน้าแรก (`/`) มี **2 โหมด สลับด้วยแท็บ** (หน้าเดียว ไม่เปลี่ยน URL):

1. **"พยากรณ์แบบไม่บันทึกข้อมูล"** (แท็บเริ่มต้น) — พิมพ์ชื่อบริษัท + เลือกประเภทธุรกิจ/อัตรา
   ดูผลพยากรณ์ทันที เหมาะกับบริษัทที่ยังไม่มีอยู่ในทะเบียนลูกค้าเลย (รายละเอียดด้านล่าง)
2. **"ค้นหาในทะเบียนลูกค้า"** — ค้นหาด้วยเลขบัญชีผู้ใช้ไฟที่บันทึกไว้แล้วใน `customers.csv`/
   `customers_local.csv`

เชื่อมกับ `amr_mapping` โดยตรง (ไม่ใช่ mockup) รันเองในเครื่องได้ทันที ไม่ต้อง build:

```bash
pip install -r requirements.txt
python web/app.py
# เปิดเบราว์เซอร์ที่ http://localhost:5000
```

โครงสร้าง: `web/app.py` เป็น Flask backend เปิด endpoint หลายตัว (`GET /api/customers`
รายชื่อทั้งหมด, `GET /api/forecast/<account_no>` ผลพยากรณ์ของรายนั้น,
`POST /api/forecast-adhoc` พยากรณ์แบบไม่บันทึกข้อมูล ฯลฯ) และเสิร์ฟหน้าเว็บ static
จาก `web/static/` (HTML/CSS/JS ธรรมดา ไม่มี framework/build step)

⚠️ **`data/reference/customers.csv` เป็นข้อมูลลูกค้า "สมมติ" สำหรับสาธิตเท่านั้น**
(ตั้งชื่อขึ้นต้นด้วย `DEMO-`) — ห้ามใส่ข้อมูลลูกค้าจริง (ชื่อ/เลขบัญชี/เลขมิเตอร์จริง)
ลงไฟล์นี้เพราะ repo เป็น public

### พยากรณ์แบบไม่บันทึกข้อมูล (แท็บเริ่มต้นของหน้าแรก)

อีกทางเลือกหนึ่งสำหรับดูผลพยากรณ์ของบริษัทที่ **ยังไม่มีอยู่ในทะเบียนลูกค้าเลย** (ไม่ต้อง
เพิ่มลง `customers.csv` หรือ `customers_local.csv` ก่อน) — แท็บนี้ให้พิมพ์ชื่อบริษัท +
เลือกประเภทธุรกิจ/อัตรา + KVA (ไม่บังคับ) แล้วดูผลพยากรณ์ทันที (เดิมเคยเป็นหน้าแยก
`/new-forecast` — ตอนนี้รวมเข้าหน้าแรกเป็นแท็บแล้ว สลับไปแท็บ "ค้นหาในทะเบียนลูกค้า" ถ้า
ต้องการค้นหาด้วยเลขบัญชีที่บันทึกไว้แล้วแทน; `/new-forecast` เก่ายัง redirect มาหน้านี้ให้
เผื่อมี bookmark เก่าอยู่)

จุดสำคัญ: **ชื่อบริษัทที่พิมพ์ในฟอร์มนี้ไม่ถูกส่งไปที่เซิร์ฟเวอร์เลย** — ฝั่ง JavaScript
(`web/static/app.js`) ส่งแค่ `business_type_code` / `rate_code` / `contract_kva` ไปที่
`POST /api/forecast-adhoc` เท่านั้น ชื่อบริษัทใช้แสดงผลในเบราว์เซอร์อย่างเดียว ฝั่ง server
เอง (`web/app.py`) ก็ไม่มี parameter รับชื่อบริษัทด้วยซ้ำ และไม่มีการคำนวณใดถูกบันทึกลง
ดิสก์/log ที่ไหนทั้งสิ้น — ปิด/รีเฟรชหน้านี้แล้วข้อมูลหายไปทันที จึงพิมพ์ชื่อบริษัทจริงได้
โดยไม่มีความเสี่ยงที่จะหลุดเข้า repo public เลย ต่างจาก `customers_local.csv` ที่ยังต้องพึ่ง
`.gitignore` (ไฟล์มีอยู่จริงบนดิสก์ แม้จะไม่ถูก commit ก็ตาม)

## นำเข้า AMR อัตโนมัติผ่านเว็บ (หน้า Admin)

เว็บแอปมีหน้า `/admin` ("นำเข้า AMR (Admin)") ให้กดปุ่มเดียว **ดาวน์โหลด AMR จริงจากเว็บ
PEA ผ่าน Selenium → คำนวณโปรไฟล์ P/OP/H → บันทึกลง `load_profiles.csv` แบบ anonymized**
ทันที โดยไม่ต้องรันสคริปต์เองทีละขั้น

### ⚠️ ข้อกำหนดก่อนใช้งาน (สำคัญมาก)

1. **ต้องรันในเครื่องที่มี Google Chrome ติดตั้งอยู่และเข้าเว็บ `amr.pea.co.th` ได้จริง**
   (ใช้ไม่ได้ใน CI/sandbox ทั่วไป — ฟีเจอร์นี้ทดสอบแล้วเฉพาะ logic การประมวลผล ไม่ได้ทดสอบ
   การ login จริงในสภาพแวดล้อมที่พัฒนา)
2. **ห้าม hardcode username/password ลงโค้ดเด็ดขาด** — กรอกได้ 2 ทาง:
   - **กรอกในฟอร์มหน้า `/admin` โดยตรง** (เหมาะถ้ามีหลายบัญชี คนละ username/password กัน
     เช่นมีเป็นร้อยบัญชี) — ใช้แค่ครั้งเดียวสำหรับงานนั้น **ไม่ถูกบันทึกลงดิสก์/log ที่ใดเลย**
     ส่ง Flask (`localhost` เท่านั้น) แล้วส่งต่อให้ Selenium ทันที
   - **ตัวแปรสภาพแวดล้อม** `PEA_AMR_USERNAME` / `PEA_AMR_PASSWORD` (ดู `.env.example`) —
     ใช้เป็นค่า default เมื่อไม่ได้กรอกในฟอร์ม เหมาะถ้ามีบัญชีหลักบัญชีเดียวที่ใช้บ่อย

   ```bash
   # ตั้งเป็น default (ไม่ตั้งก็ได้ ถ้าจะกรอกในฟอร์มทุกครั้งแทน)
   # macOS/Linux
   export PEA_AMR_USERNAME="เลขบัญชีของคุณ"
   export PEA_AMR_PASSWORD="รหัสผ่านของคุณ"
   python web/app.py

   # Windows PowerShell
   $env:PEA_AMR_USERNAME="เลขบัญชีของคุณ"
   $env:PEA_AMR_PASSWORD="รหัสผ่านของคุณ"
   python web/app.py
   ```

3. **ไฟล์ดิบที่ดาวน์โหลดมาจะถูกลบทิ้งทันทีหลังประมวลผลเสร็จเสมอ** (ดาวน์โหลดลงโฟลเดอร์
   temp ชั่วคราว ไม่ใช่ในโฟลเดอร์ repo) — มีแต่ตัวเลข P/OP/H ที่เฉลี่ยแล้วเท่านั้นที่ถูกเขียน
   ลง `load_profiles.csv` ไม่มีชื่อ/เลขบัญชี/เลขมิเตอร์ลูกค้าหลงเหลืออยู่เลย

### วิธีใช้

1. รัน `python web/app.py` (ตั้งค่า env var ไว้ก่อนก็ได้ ถ้าจะกรอกในฟอร์มทุกครั้งก็ข้ามได้)
2. เปิด `http://localhost:5000/admin`
3. กรอก username/password เข้าเว็บ AMR ของ PEA (ถ้าไม่ได้ตั้งเป็น env var), เลขบัญชีผู้ใช้ไฟ
   ที่จะดึงข้อมูล (คั่นด้วย `,` ถ้ามีหลายราย — **ต้องเป็นบัญชีที่ username/password ที่กรอกเข้าถึงได้**),
   เลือกประเภทธุรกิจ, ใส่รหัสอัตรา, ช่วงวันที่
4. กด **"ดาวน์โหลดและนำเข้า"** — จะเห็น log แบบ real-time และผลลัพธ์ P/OP/H เมื่อเสร็จ

ทดสอบ flow ทั้งหมดแล้วในสภาพแวดล้อมที่พัฒนา (ฟอร์ม → job → background thread → cleanup)
ยกเว้นขั้นตอน login จริงเข้าเว็บ PEA ซึ่งต้องมี Chrome + เน็ตจริงที่เข้าถึง `amr.pea.co.th`
ได้ — เมื่อเชื่อมต่อไม่ได้ ระบบจะจับ error และแสดงผลว่า "ไม่สำเร็จ" พร้อมเหตุผลบนหน้าเว็บ
(ไม่ crash เซิร์ฟเวอร์) และลบไฟล์ temp ทิ้งให้เสมอไม่ว่าจะสำเร็จหรือไม่

โค้ดเบื้องหลัง: `src/amr_mapping/amr_downloader.py` (พอร์ตจากสคริปต์ Selenium เดิมของผู้ใช้
`AMR_PEA_Selenium.py` — ปรับให้รับ credential เป็นพารามิเตอร์แทนการ hardcode) และ
`src/amr_mapping/amr_import.py` (เชื่อม downloader → `pea_ingest` → `load_profiles.csv`)
